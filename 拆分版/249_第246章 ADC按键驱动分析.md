首先在第9 行，调用了iio_read_channel_processed()函数从IIO 通道读取处理后的ADC 值，关于iio_read_channel_processed()函数的具体内容如下所示：代码清单246.8
```c
int iio_read_channel_processed(struct iio_channel *chan, int *val)
{
    int ret;
    mutex_lock(&chan->indio_dev->info_exist_lock);
    if (chan->indio_dev->info == NULL) {
        ret = -ENODEV;
        goto err_unlock;
    }
    // 检查通道是否支持PROCESSED 类型的信息
    if (iio_channel_has_info(chan->channel, IIO_CHAN_INFO_PROCESSED)) {
        ret = iio_channel_read(chan, val, NULL, IIO_CHAN_INFO_PROCESSED);
    } else {
        ret = iio_channel_read(chan, val, NULL, IIO_CHAN_INFO_RAW);
        if (ret < 0)
            goto err_unlock;
        ret = iio_convert_raw_to_processed_unlocked(chan, *val, val, 1);
    }
err_unlock:
    mutex_unlock(&chan->indio_dev->info_exist_lock);
    return ret; // 返回结果
}
```
该函数的重点在于第12-19 行的逻辑判断，但由于不支持IIO_CHAN_INFO_PROCESSED 类型的数据，所以进入的是第二个分支，通过iio_channel_read()函数读取通道的原始值，读取完成之后通过iio_convert_raw_to_processed_unlocked()函数将原始值转换为处理后的值。然后回到adc_keys_poll 函数，继续向下分析。

在第10-12 行进行逻辑判断，如果读取失败，则将AD 值设置为keyup_voltage，表示按键松开时候的电压，从而模拟按键松开状态。如果读取成功则在15-21 行进行匹配按键映射表，遍历按键映射表，找到与当前AD 值最接近的按键，计算每个按键电压与当前ADC 值的差值，并更新最小差值及对应的按键码。接下来的第25-34 行是3 个不同的逻辑判断，具体逻辑内容如下所示：（1）如果当前ADC 值与按键松开电压的差值小于最小差值，则认为没有按键按下，按键码设置为0。（2）如果上次按下的按键与当前按键不同，调用input_report_key 上报按键释放事件（值为0）。（3）如果当前按键有效，调用input_report_key 上报按键按下事件（值为1）。最后在第40 行更新最后按下的按键状态，以便下次轮询时进行比较。在本章末尾对ADC 按键的核心函数adc_keys_poll()进行总结，它的主要作用是通过定期轮询ADC 按键设备的状态，从IIO 通道读取处理后的ADC 值，并根据按键映射表匹配当前ADC值以判断是否有按键被按下或释放，同时结合按键松开电压确保状态的准确性，最后通过输入子系统上报按键事件并同步更新按键状态。至此关于ADC 按键驱动程序就分析完成了。
