driver_attach 会遍历总线上已注册的所有设备，检查是否匹配。如代码清单112.10 所示。代码清单112.10
```c
// drivers/base/dd.c
int driver_attach(struct device_driver *drv)
{
  return bus_for_each_dev(drv->bus, NULL, drv, __driver_attach); // 遍历总线上的设备列表
}
static int __driver_attach(struct device *dev, void *data)
{
  struct device_driver *drv = data;
  if (!driver_match_device(drv, dev)) // 调用总线的match 函数判断是否匹配
    return 0;
  return driver_probe_device(drv, dev); // 匹配成功，触发驱动的probe 函数
}
```
通过以上分析可以得出，驱动注册到总线后会通过driver_attach()函数遍历总线上已有设备，然后再次调用driver_match_device()函数进行驱动和设备的匹配。此时因为driver 和device都已经加载，所以可以成功匹配。显然，无论是driver 加载还是device 加载，最终都会调用driver_match_device 进行匹配。因此，无论谁先谁后，最终都能够被匹配到。至此，加载驱动和加载设备先后顺序分析完毕。
